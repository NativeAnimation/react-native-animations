# Verified agent package formats

Checked online on **October 12, 2026**. These are authoring formats, not claims of directory approval. Only documented fields are used.

| Agent | Official source | Essential format |
| --- | --- | --- |
| Claude Code | https://code.claude.com/docs/en/plugin-marketplaces | Repository root `.claude-plugin/marketplace.json`: `name`, `owner.name`, `plugins[]` with `name` and a `source` relative to the repository root. Registering a marketplace and installing its plugin are separate operations. |
| Claude Code | https://code.claude.com/docs/en/plugins-reference | Plugin metadata lives in `.claude-plugin/plugin.json`; component paths start with `./`. Skills live under `skills/<name>/SKILL.md`. Root `.mcp.json` declares `mcpServers` with `command` and `args`. `claude plugin validate <path>` checks plugin and marketplace manifests; `--plugin-dir` loads a local plugin for one session. |
| Cursor | https://cursor.com/docs/reference/plugins | `.cursor-plugin/plugin.json` accepts `name`, `version`, `description`, `author`, `skills`, and `mcpServers`. Default discovery uses `skills/` and root `mcp.json`; explicit paths stay inside the plugin. A repository with nested plugins uses root `.cursor-plugin/marketplace.json`. |
| Cursor | https://cursor.com/docs/plugins | Local development packages are copied into `~/.cursor/plugins/local/<name>` and require a reload. Outside symlinks are skipped. Local imports may be restricted by administrators. Public listing requires owner submission and review. |
| Cursor MCP | https://cursor.com/docs/mcp/install-links | `cursor://anysphere.cursor-deeplink/mcp/install?name=<name>&config=<base64>` uses a base64 encoded JSON object keyed by server name. URL-encode the query value. This installs the MCP connection only, not a skill or a plugin. |
| Cursor CLI | https://cursor.com/docs/cli/reference/parameters | Current binary is `agent`; `-p`, `--plugin-dir`, `--workspace`, `--output-format stream-json`, `--approve-mcps`, `--trust`, and `--force` are documented. The runner also accepts an installed `cursor-agent` alias after checking its help. |
| OpenAI | https://developers.openai.com/plugins/ and https://developers.openai.com/plugins/build/plugins | Portable packages use root `plugin.json` and `mcp.json`. The supported Codex compatibility layout uses `.codex-plugin/plugin.json`, `skills: "./skills/"`, and `mcpServers: "./.mcp.json"`. This kit uses the compatibility layout, without a competing portable manifest. |
| Codex local distribution | https://developers.openai.com/plugins/build/plugins#install-a-local-plugin-manually | Repo catalogs normally use `.agents/plugins/marketplace.json`; the documented legacy `.claude-plugin/marketplace.json` location is also supported. The shared catalog uses that location because this workspace's root `.agents/` is read-only. Local client support can vary. |
| Codex CLI | https://developers.openai.com/codex/cli/reference | Noninteractive runs use `codex exec`. Installed CLI help also verifies `codex plugin marketplace add <source>` and `codex plugin add <plugin>@<marketplace>`; `plugin install` is not a current CLI command. |
| OpenAI submission | https://developers.openai.com/plugins/deploy/submission | A ZIP contains the plugin at its root. Codex listing metadata requires an `interface` and square icons, including `logo` and `composerIcon`. Public MCP submission needs a remote HTTPS endpoint, publisher verification, connection checks, and review materials. |
| Expo fixture | https://docs.expo.dev/more/create-expo/ | `create-expo-app --template blank-typescript --yes --no-install` is documented. The runner checks SDK 57 before installing anything. A verified version of the same template can be pinned to avoid future `latest` drift. |

## Boundaries and unresolved items

- All three local packages launch the existing stdio server with `npx -y nativeanimation@latest mcp`. No hosted server, OAuth registration, private credentials, or invented remote URL is included.
- The OpenAI ZIP is a local Codex distribution and submission **draft**. The existing stdio MCP cannot complete the public directory's remote MCP connection flow. Do not submit this draft as a working hosted integration; the owner must first decide whether to provide HTTPS transport and authentication.
- Cursor does not document a marketplace plugin installation shell command here. The provided one-command helper copies a local package using its documented layout. CLI evaluation uses the documented `--plugin-dir`, not an invented install command.
- Skill source: `plugins/nativeanimation/skills/react-native-animations/`. All manifests point within that same plugin root; ZIP creation copies regular files, with no external symlinks.
- Baseline requested for this kit: Expo SDK 57, React Native 0.86, Reanimated 4.5, and react-native-worklets 0.10. Detect the consumer project's actual versions before choosing a piece; never silently upgrade its SDK.
- The official package registry returned `expo-template-blank-typescript@57.0.30` on October 12, 2026, with `expo: ~57.0.28` and `react-native: 0.86.3` (https://registry.npmjs.org/expo-template-blank-typescript/57.0.30). The runner pins that template, then checks the generated app before installing dependencies.
- MCP semantics were checked read-only against `web-plataforma:docs/mcp.md` and `cli/src/mcp/tools.ts`. `get_piece` takes `id`; `add_piece` takes `ids` and an absolute `project_root`. `add_piece` requires login even for free catalog entries and does not install dependencies by default.
